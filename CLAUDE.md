# Agent notes for this project

Quick orientation for continuing this build (originally scaffolded in Claude, intended to be picked up in Claude Code). Read `README.md` first for the full plan and **`PEDAGOGY.md` for how the app must teach** — this file is the short "don't relitigate these decisions" version, plus pointers.

## What's already decided (don't re-derive from scratch)

- **Static site, no backend, no build step for v1.** Plain HTML/CSS/JS. Targets GitHub Pages.
- **State lives in one `localStorage` key**, accessed only through `js/storage.js`'s functions (`getSettings`/`setSettings`, `getVocabItem`/`updateVocabItem`, `getReadingRecord`/`setReadingRecord`). Don't call `localStorage` directly from elsewhere — if a new kind of trackable data is needed (e.g. grammar-drill records), add a new top-level key to the store shape in `storage.js` and matching accessor functions, following the existing pattern, rather than inventing a new convention.
- **SRS scheduling goes through `js/srs.js`** (`scheduleReview(record, quality)` — simplified SM-2). Any new spaced-repetition surface (vocab, reading, future parsing drills) should call this same function, not a new one.
- **Theming is a shared-data/swappable-skin architecture, not per-theme forks of the app.** One HTML structure + shared data, three theme CSS files scoped by `[data-theme="classic|lexis|nous"]` and `[data-theme="…"][data-mode="dark"]`. `js/theme.js` applies `data-theme`/`data-mode` attributes on `<html>` from saved settings. When building a new screen: write the markup once, add CSS rules to *all three* theme files (not just one), don't hardcode colors in HTML — use CSS custom properties from the active theme.
- **Style is a user Settings preference**, not a fixed choice — all three themes (Classic/Lexis/Nous) are meant to ship together, switchable at any time, light/dark included.
- **No AI-graded free-text translation in v1.** Read & Translate is self-graded (reveal reference translation, learner self-rates Missed it/Close/Nailed it). Don't add a live grading API call without first setting up a separate serverless adjunct (see README's "Known limitation") — a static GitHub Pages site cannot hold the secret key that would require.
- **Only public-domain reference translations** (KJV, YLT, WEB) may be bundled. Never add ESV/NIV/NASB or other copyrighted translation text to `data/`.
- **Content is sourced, not hand-invented.** Everything under `data/` is GENERATED by `python3 scripts/build_data.py` from SBLGNT/MorphGNT (text, lemma, parse), the MorphGNT lexicon (glosses) and public-domain KJV/YLT/WEB. Frequency order is computed from MorphGNT counts (Trenchard's book is copyrighted and not copied). Never hand-edit `data/*.json`; edit `scripts/curriculum.py` (alphabet, paradigms, principal parts, lesson spine, rule text) or `scripts/build_data.py` and regenerate. Licenses and attribution: `data/LICENSES.md`.
- **PEDAGOGY.md wins.** Every feature should satisfy a labeled mandate (M1–M32). Non-negotiables: every interaction is retrieval with immediate feedback + a one-line reason (M4, M18); sessions are "due first, then new" across all history (M3); items progress MC → typed → produced by stored strength (M12, M17); readings show real Greek with every unknown word one tap from gloss + parse (M23); XP rewards due reviews / reading / production, never time-on-app (M29–M31).
- **Lexicon item id == the lemma** (NFC Unicode, e.g. `'λόγος'`). `vocabSRS` is keyed by it. Words with fewer than 10 GNT occurrences are never scheduled as vocab (`scheduleMinCount` in `curriculum.json`); they are glossed on tap only.
- **Lesson ids** look like `u01-alphabet-1`; `progress.lessonsCompleted` holds them and the lesson path derives complete/active/locked from that list (see `index.html`).

## File map

- `index.html` — lesson-path screen for all 35 Books (reads `data/curriculum.json`, derives lesson state from progress), due-review banner, install banner; the Profile tab opens Settings.
- `settings.html` — Settings / Profile. Theme + mode (the original switcher lives here now), pronunciation, translation, progress stats, install button, backup (`exportStore`) / restore (`importStore`) / reset (`resetProgress`) — all through `storage.js`. Credits text satisfies the attribution rule in `data/LICENSES.md`; keep it when redesigning.
- `placement.html` + `js/placement.js` — placement test. `buildPlacement` samples 6 questions per grammar Book (3 vocab gloss-mc via `drill.makeQuestion`, 2 paradigm cells via `grammar.cellQuestion`, 1 principal part), `placementIndex(scores)` = Books passed (pass mark 5/6, sequential, stop at first failure), `knownRecords(passedUnits, …)` = lessons to complete + vocab/form records at repetitions 2, due in 14 days. Applied only on confirmation; never overwrites existing records. Linked from the path (until a lesson is completed) and Settings.
- Theme before first paint: `js/recover.js` (classic, first in `<head>`) reads the store and sets `data-theme/mode/font-*`, `color-scheme` and a per-theme background on `<html>` before any CSS, so dark mode never flashes white; `theme.js` keeps `<meta theme-color>` in step via `THEME_BG`. Keep the background table in both files in sync with `css/theme-*.css`.
- Locking: `index.html`'s `lessonState` is sequential across the whole curriculum (complete / active = first incomplete / open = previous complete / locked); locked nodes are not clickable. Escape hatches: the placement test and `settings.unlockAll`.
- Resume: `storage.sessions['<screen>:<lesson|due>']` holds a snapshot with `savedAt` (24 h TTL; `getSession/saveSession/clearSession`). Every session screen saves on each step once past the first, offers `view.renderResume` (Resume / Start over) on reopen, and clears on the summary. Drill snapshots store item ids and rehydrate from the lexicon; reading stores verse ids + reveal lemmas; alphabet, grammar and placement store their step arrays as-is. Sessions are excluded from backups.
- Occurrences: `data/occurrences.json` (first 8 verses per lemma) feeds the Lexicon's "In the New Testament" chips and "Read it in context"; `read.html?…&lemma=<lemma>` highlights every hit in the chapter (`.w.hit`) and opens the Word tab on the first hit in the target verse, one-shot.
- Desktop session layout: on ≥900px without the sidebar the footer is static under the content, the header sticky, options two-column (`.options.long` stays one), a keyboard hint sits beside the button, and `html[data-screen="reading"]` lays the reading body out as verse | sticky gloss panel. Phone rules are untouched.
- Dev mode: `js/dev.js` (`isDev`, `enableDev(password)` — password `Logos`, client-side only, deliberately not security). When on: `<html>` gets a fixed DEV badge (`initDev()` on every page), `index.html` treats every lesson as open, session screens add a header button via `devSkipButton(onSkip)`, drill/grammar feedback appends the raw SRS record, and Settings → Developer offers Jump to lesson, Seed sample learner (Books I–II via `placement.knownRecords`, a third due), Make everything due, Advance a day (shifts due dates and lastActiveDate back one day — there is no global clock offset). Test data made in dev mode is real store data; Reset clears it.
- Handwriting: `js/scribe.js` `createScribe(container, {guide, lines, width, height})` — pointer-event canvas, DPR-scaled, undo/clear, `coverage()` (share of guide pixels with ink within 9 px) and `inkLength()`. Handwriting is an opt-in beta (`settings.handwriting`, Settings → Learning, Beta tag): when on, alphabet lessons insert a `trace` step after every letter intro (pass at 55% coverage, 3 XP, Skip allowed) plus `trace-word` steps for the lesson's words, the Lexicon detail sheet gets a "Trace it" pad (`#traceWord`, 2 XP), and Write & translate assignments offer the on-screen pad. When off, none of those appear (`buildAlphabetSession({handwriting})`). Reading lessons end with a Write & translate assignment (`renderAssignment` in `reading.html`): copy the first verse (paper or pad), translate from memory, reveal references, self-rate; stored on the verse's `readingHistory` record as `written`, `myTranslation`, `writtenRating`; achievements count `written`.
- Installed app: pages use `black-translucent` status bar with `env(safe-area-inset-*)` padding on the top bars, footer and gloss sheet; `100dvh` alongside `100vh`; `overscroll-behavior: none` on html/body and `contain` on scrollers; `touch-action: manipulation` on controls (`none` on the pen canvas). Manifest has `id` and `display_override`.
- Deploy safety: `sw.js` is network-first with `cache: 'no-cache'` for app files (cache = offline fallback); `js/pwa.js` reloads once on `controllerchange`; `js/recover.js` (classic script, first in every `<head>`) clears caches/SW and reloads once when a module fails to link. This exists because GitHub Pages' 10-minute HTTP cache + a stale worker once served an old `storage.js` to a new `index.html` (missing export → blank page). Keep `recover.js` first in the head of any new page.
- PWA: `manifest.json`, `sw.js`, `js/pwa.js`, `icons/`. Every page imports `initPwa()` and carries the manifest/theme-color/apple meta tags in its `<head>`; copy that head block into any new page. `sw.js` precaches the shell + core data (stale-while-revalidate) and caches units/chapters on use (network-first). **Bump `CACHE_VERSION` in `sw.js`** when you change the shell in a way old caches must not serve. Everything is relative-path so the GitHub Pages sub-path works. Regenerate icons from `icons/icon.svg` with `qlmanage -t -s 1024` + ImageMagick (ImageMagick alone lacks the font).
- `css/base.css` — shared/reset styles, theme-independent layout.
- `css/theme-{classic,lexis,nous}.css` — one file per theme, each defining the same set of CSS custom properties (`--bg`, `--surface`, `--ink`, `--muted`, `--border`, `--accent`/theme-specific accent names, `--font-display`, `--font-body`) plus a `[data-mode="dark"]` override block. Keep the custom-property *names* consistent across all three files so shared component CSS in `base.css` can reference them theme-agnostically.
- `drill.html` + `js/drill.js` — the vocab drill. `drill.js` is pure logic (no DOM) and is the reference implementation of the session rules: due items from all history first (M3), intro card immediately followed by recall for new words (M4/M9), one same-session second pass that does not advance the schedule, format by SM-2 repetitions (`formatFor`: gloss-mc → greek-mc → gloss-type → greek-type, M12/M17), distractors of the same part of speech / nearby frequency / look-alikes with names kept apart (M6), retries and second-pass answers earn no schedule change and little XP (M30), misses requeue four steps later and reset the item (M19). Build parsing/reading drills on the same pattern (a logic module + a view), reusing `ratingFor`/`xpFor` semantics.
- `alphabet.html` + `js/alphabet.js` — Book I's four alphabet lessons. `alphabet.js` has the reusable Greek-text helpers (`transliterate`, `syllabify`, `accentOf`, `hasRough`, `hasSubscript`, `stripMarks`) that the reading screen will also need. Word pools come from real data at runtime: example words from the lexicon, iota-subscript forms from `paradigms.json`, accented words (incl. graves) from John 1 in `gnt/john.json`. Elided tokens (ἐπ’) are filtered out.
- `reading.html` + `js/reading.js` + `js/morph.js` — Read & Translate. "Known" means the lemma has a `vocabSRS` record; words under 10 occurrences are `glossOnly` (tapping them never costs XP). A reading lesson whose `vocab[]` has unstudied words first shows a gate that sends the learner to `drill.html?lesson=<id>&return=reading.html?lesson=<id>`; the drill does not mark reading lessons complete (only reading does). `morph.js` (`describeParse`, `describePos`, `parseSlots`) is the one place parse codes are decoded — reuse it in parsing drills. Verse ratings go through `scheduleReview` into `readingHistory`; due verses are not yet pulled into a daily session (open item).
- `grammar.html` + `js/grammar.js` — grammar/verb lessons (Phase 3) and the due-forms review (`?mode=due`). Session: rule → paradigm table → up to 8 cells (unseen/due first) as `parse-mc` or, once a cell has 2+ successful reviews, `form-type` (typed, accent-insensitive, movable ν optional) → up to 5 real attested forms of the lesson's own words from `data/forms.json` filtered to the paradigm's tense/voice/mood (or any case for nominals) → strange-verb cards and principal-parts questions. Distractors are the paradigm's own confusable cells (closest parse first); paradigms with under 4 cells borrow sibling cells of the same kind. SRS ids: `<paradigmId>|<parse>` and `irr|<lemma>|<partIndex>` in `storage.formSRS`. The path routes lessons that have paradigms or an irregular pool here; the summary hands off to `drill.html` for the lesson's words (which marks the lesson complete). The due banner on the path chains `drill.html?mode=due&return=grammar.html?mode=due`.
- `scripts/smoke.mjs` — `node scripts/smoke.mjs` validates every cross-reference in `data/` and builds a session for all 453 lessons with the real logic modules. Run it before every deploy and after any change to `scripts/curriculum.py`, the data build, or a logic module. It has already caught real bugs (single-option multiple choice).
- `js/nav.js` — the bottom nav for top-level pages (`renderNav(container, active)`); Progress is shown only when `settings.showProgress` is true. Every top-level page has `<div class="bottom-nav" id="nav"></div>`; session screens (drill, alphabet, grammar, reading) have a back button instead.
- `read.html` — Read tab: whole-NT parallel reader. Books/chapters from `data/stats.json` (`number`, `chapters`, `greekTitle`), text from `data/gnt/<slug>.json`, glossing via `reading.js` + `morph.js`. Not a lesson: nothing scheduled or scored; the "Study this chapter" button links to the curriculum's reading lesson for that chapter when there is one. Remembers `settings.lastRead`; `settings.markUnknown` toggles the dotted underline.
- `lexicon.html` + `js/lexicon.js` — Lexicon tab. `searchLexicon(items, {query, filter, records})` handles Greek (accent-insensitive prefix > substring) and English (gloss alternative exact > prefix > substring); `statusOf` gives strong/learning/due/new/gloss-only. `item.lesson` (added by the build) links to the teaching lesson. "Add to my words" schedules a word as new. `?q=<lemma>` deep-links the detail sheet (the reader's gloss sheet uses it).
- `progress.html` + `js/achievements.js` — opt-in Progress tab. `evaluate({store, curriculum, lexicon})` returns achievements (Habit, Vocabulary, Reading, Grammar, Path, The New Testament, XP), coverage meters (share of NT running words covered by studied / strong lemmas) and counts. First-unlock dates are recorded in `progress.achievements` via `recordAchievements`. Achievements reward learning behaviours only (M29); there is deliberately no leaderboard.
- `js/chain.js` — the daily review chain. `index.html` computes which of drill/grammar/reading have due items and starts `chainHref([...])`; each due-mode screen ends with `nextInChain(params)` / `chainLabel(params)`. `reading.html?mode=due` reviews up to 20 due verses (oldest first) across any books. Any new SRS surface joins the chain by adding a key to `SCREENS` and a due-mode to its screen.
- `js/speech.js` — pronunciation. `speak(text)` uses the device Greek voice for the Koine scheme, otherwise `respell()` (syllabified, stressed syllable upper-cased) through an English voice. `speakerHtml()` + `initSpeech()` (click delegation on `[data-speak]`) put a button anywhere; `autoSpeak()` honours `settings.autoSpeak`; `settings.speechRate` (0.5–1.1, default 0.7) sets the rate via `clampRate`. **Always pass Greek through `toMonotonic()` before a Greek voice** (polytonic breathings/circumflex/subscript silence modern Greek TTS; this is why ὁ said nothing). Whole verses go through `speakVerse()` (clauses from `phraseChunks`, 350 ms after commas, 650 ms after stops/raised dots, 8% slower); speaker buttons for verses carry `data-speak-mode="verse"` (`speakerHtml(text, {verse: true})`).
- Study helps: `scripts/build_sword.mjs` (+ `scripts/sword/*.mjs`, parsers ported from the author's BibleStudy project) downloads CrossWire's StrongsGreek, RWP and TSK modules and writes `data/strongs-greek.json` (entries keyed by Strong's number without the G, only numbers our lexicon references + one hop of "from N" links), `data/rwp/<slug>.json` and `data/xrefs/<slug>.json` (per NT book, `chapters[ch][v]`). Loaders in `data.js`: `loadStrongs()` + `strongsFor(item, entries)`, `loadWordPictures(slug)`, `loadXrefs(slug)`. The reader's drawer (`read.html`, `#sheet`) has Word / Word Pictures / Cross-refs tabs; tapping a verse number selects the verse. Cross-ref targets outside the NT are shown grey and inert (we hold no OT text). `js/refs.js` parses "Jn 3:16"-style references for the jump box and recognises OT names so the UI can say they are not included. `build_sword.mjs` sanitises the StrongsGreek module (the CrossWire copy carries stray CJK glosses and `{}` pronunciation braces in ~50 entries; `cleanDef`/`cleanPron`/`cleanTranslit`/`cleanLemma` strip them and `DEF_OVERRIDES` hand-fixes G3588 and G3958) — re-run the scan in the build log ("CJK left") after any parser change. Licensing: Strong's and TSK public domain; RWP "Copyrighted; Free non-commercial distribution" per its conf — keep the app non-commercial or drop RWP.
- Voice is an opt-in beta: `settings.voice` (default false) gates `speak`/`speakVerse`/`autoSpeak` and hides speaker buttons (`initSpeech` adds `no-speech` when off). The Settings switch carries the beta warning; auto-speak, speed and try-it rows are disabled until it is on.
- iOS mute switch: `sfx.js` plays a generated silent WAV through an `<audio>` element on each gesture (`nudgePlaybackSession`) so Web Audio cues sound with the ringer on silent; do not remove it when refactoring sound.
- `js/sfx.js` — answer cues synthesized with Web Audio (`playCorrect`, `playWrong`, `playTick`, `playComplete`; `settings.sfx`). Call from the answer handler of every session screen; `initSfx()` warms the context on the first gesture (iOS). `session-view.js` has its own copy of `speakerHtml` and a `speak` option on `renderQuestion` so it stays dependency-free. No audio files: keep it that way unless a licensed recording set is added.
- `study.html?book&chapter&verse[&focus=wp|xref|words][&back=…]` — the long-form page behind every "Read more": the verse, full Word Pictures, all cross-references, every word glossed. Drawers and gloss panels show only excerpts (`excerpt()` in read.html, first ~320 chars) plus a Read more link; Strong's definitions link to the Lexicon rather than expanding inline. The reader's drawer is capped at 46vh with its own scroller (`.sheet-scroll`) and a pinned close button; everything in it wraps (`overflow-wrap: anywhere`) so nothing scrolls sideways on a phone.
- Phone reader ergonomics (≤899px): the bottom nav is fixed, the reader bar sticky, floating prev/next chapter buttons (`.fab`) sit above the nav, the reader/lexicon/settings/path bodies scroll with the page (the body is the scroller because html/body have height 100% + overflow-x hidden), and `html, body { overflow-x: hidden }` guards against horizontal scroll.
- `js/session-view.js` — the shared session UI (`SessionView`: `renderIntro`, `renderQuestion` with options or typed input + Greek keyboard, `markAnswer`, `showFeedback`, `renderSummary`, keyboard shortcuts 1–6 / Enter). Every session-style screen (drill, alphabet, future parsing and reading) uses it; do not re-implement cards or the footer per screen. Markup contract: `#body`, `#footer`, `#continueBtn`, `#progressFill`.
- `js/data.js` — the only module that fetches `data/*.json`; everything is cached in memory. Use `loadLesson(id)`, `loadLexicon()`, `loadBook(slug)`.
- `js/storage.js`, `js/srs.js`, `js/theme.js` — see above. `srs.js` has a 4th rating `good` (quality 4) for objectively-correct recognition answers; `storage.js` has `recordActivity()` (streak, idempotent per day; call only after real work — M31), `addXp()`, `markLessonCompleted()`, `getAllVocabRecords()`.
- Layout: mobile-first, with one desktop block at the end of `css/base.css` (`@media (min-width: 900px)`). `renderNav` adds `has-sidebar` to `<html>`; pages with the nav get a fixed 232px left sidebar (brand + stats + tabs) and a wide column, the path gets a sticky Books list (`.path-layout` = `.book-list` + `.path-main`), the Lexicon is two panes (`.lex-layout`, detail sticky, placeholder when nothing is selected), the reader's gloss sheet docks bottom-right. Session screens (no nav) stay a centered, framed 760px column with the footer matched to it. Short landscape phones (`max-height: 520px and landscape`) tighten spacing and put options in two columns. When adding a top-level page: include `<div class="bottom-nav" id="nav"></div>` and call `renderNav`; when adding a session page: keep the `#body/#footer` contract and it inherits the framed layout.
- Fonts: three tokens, `--font-greek` (Greek text: prompts, verses, paradigms, lemmas), `--font-display` (headings) and `--font-body`. Each theme sets display/body and `--font-greek: var(--font-display)`. Learner overrides live in `settings.fontGreek/fontDisplay/fontBody` ('theme' or a `FONTS` id in `theme.js`) and are applied by `applyTheme` as `data-font-greek/display/body` on `<html>`, matched by `html[data-font-…]` rules at the end of `base.css`. **New Greek-text components must use `var(--font-greek, var(--font-display))`, not `--font-display`.**
- CSS: components live in `css/base.css` and use only tokens; the theme files define the tokens (now including `--ok`, `--ok-tint`, `--bad`, `--bad-tint` for feedback states, in all three themes × light/dark). Note `[hidden]` needs an explicit `display: none` override on any element whose class sets `display`.
- `data/curriculum.json` (index) + `data/units/<id>.json` (full lesson content: `vocab[]`, `paradigms[]`, `rule`, `alphabet`, `irregular[]`, `reading{verseIds, coverage}`), `data/lexicon.json`, `data/forms.json`, `data/paradigms.json`, `data/irregular-verbs.json`, `data/alphabet.json`, `data/stats.json`, `data/gnt/<book>.json`. Shapes are documented in each file's `_meta` and in README § Project structure.
- `scripts/build_data.py` + `scripts/curriculum.py` — the content pipeline. Run the build after any change there; it validates lemmas, paradigm cells (against attested GNT forms) and core-vocabulary coverage, and fails loudly.

## Design tokens reference (extracted from the mockups)

**Classic:** `--primary:#16795A; --primary-dark:#0F5A41; --gold:#D9A521; --coral:#E25C4B;` fonts: Baloo 2 (display) + Noto Sans (body).
**Lexis:** `--bg:#F3E9D2; --ink:#3B2417; --accent:#7A1F1F; --gold:#B8860B;` fonts: EB Garamond (display) + Noto Serif (body). Manuscript/parchment feel — double gold rules, wax-seal-style circular nodes.
**Nous:** `--bg:#FFFFFF; --ink:#111111; --accent:#0047FF;` fonts: Space Grotesk (display) + Noto Sans (body). Minimal editorial feel — numbered list rows instead of a path, no ornament.

Full color/dark-mode values are in `css/theme-*.css` — the above is just enough to recognize which theme you're looking at.
